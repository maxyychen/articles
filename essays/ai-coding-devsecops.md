# Small Batches, Clear Goals: How AI Coding Fits DevSecOps

DevSecOps rests on a simple idea: software should evolve through small, well-scoped changes, with security built into every step rather than bolted on at the end. Small batches are easier to test, review, and roll back.

As AI coding tools like Claude Code mature, I've noticed something: the way they work best maps almost perfectly onto DevSecOps principles.

## Small batches are the shared foundation

DevOps learned long ago that small change sets reduce risk. Defects surface faster and blast radius shrinks. AI behaves the same way. Give it a narrow task with a clear goal—"refactor this function to handle null inputs"—and it delivers with high precision. Ask it to "build the entire payment system" and quality degrades as ambiguity compounds. AI accuracy is a function of scope. That's exactly what DevSecOps already optimizes for.

## Clear goals are specifications

Every DevSecOps change comes with a definition of done. A precise prompt is the same thing—a micro-specification. The clearer the acceptance criteria, the higher the output fidelity. Effective prompting is just the rigor good engineering teams already practice: state intent explicitly, bound the problem.

## Security stays in the loop

Security checks should run continuously, not as a final gate. Small batches make that feasible—each increment can be scanned, tested, and reviewed before merging. AI fits naturally: it generates code with its tests, explains its reasoning for review, and runs through the same pipeline (static analysis, dependency scanning, automated tests) as any contributor. Trust comes from verification, not authorship.

## The human is the orchestrator

DevSecOps shifts humans from manual labor toward orchestration—defining pipelines, setting policy, reviewing changes. AI extends this. The engineer decomposes a large goal into small tasks, delegates each to the AI, and validates the result. The human still owns architecture, security posture, and final review.

The alignment isn't accidental. Small batches, clear goals, continuous verification, and built-in security are simultaneously the conditions under which AI does its best work and the practices DevSecOps was built on.

The teams that succeed with AI coding will be the ones already fluent in DevSecOps—because they're practicing the same discipline.
